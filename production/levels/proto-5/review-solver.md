Solver review (read only). Verdict: no way found for a baked level to be unsolvable, and no ray mismatch. The carver, solver and DragonController all walk rays through StageRules.Next with the same RayStepCap, and a ray that loops counts as blocked in all three. The solver is an exact fixed point because removals only free cells.

1. Required - StageLoader.cs:648-653 FindHintableDragon ignores IsLocked (IsLocked now includes the link). Scenario: on the linked-lock level the first dragon in solve order whose own ray is clear can be a link-locked one, so Hint pulses a dragon that only shakes. Fix: add `&& !dragon.IsLocked`.
2. Required - StageManager.cs:46 `DragonExited(DragonController who = null)`. A caller that omits `this` never fires OnSpecificDragonLeft, so every dragon linked to it stays locked forever, a silent softlock the solver cannot see. Today both call sites pass `this` (DragonController.cs ExitStepOnce and FinishPortalExit). Fix: make the parameter required.
3. Required - StageRules.cs:72-94 Validate checks too little, and its comment overstates. It does not check that dragon cells, rocks and portal cells are disjoint, that cells are in bounds, or that the portal count is exactly 2. FromStage silently ignores portals[2+] (and a lone portal), but StageLoader.cs BuildRocksAndPortals still draws a ring for every entry. Scenario: a hand-edited JSON puts a dragon cell on a portal. The solver steps over the ring, but in the game that dragon's head is "on a ring" and teleports at DragonController.cs TryAdvance. The "must point at a LOWER index" comment is not enforced (a higher index still solves, since the solver is a fixed point). Fix: add the checks, or soften the comment.
4. Optional - DragonController.cs OnOtherDragonLeft/OpenLockBadge. If a count lock and a link are both set, the count reaching 0 removes the badge while IsLocked is still true through the link. Not reachable today, because the proto pack sets lockThreshold = 0 (ProtoPack.cs:108).
5. Optional - ice. The game hardcodes iceStage = 2, while the solver uses StageRules.MaxIceTaps. Changing one without the other breaks the tap counts. A blocked iced dragon is also cracked and shattered by taps before its ray is checked (HandleTap ordering), so the second tap costs a life. This is not an unsolvability problem.
6. Optional - the ray walk is copied six times: StageRating, StageCarver.RayIsClear, DragonController.RayReachesEdge, ProtoLevelBaker.RayFreeNow and RaysOverCells, and the test's RayLeaves. The tests share only StageRules.Next. No PlayMode test ties the game to the solver. Consider one shared `StageRules.RayLeaves(...)`.
7. Optional - ProtoLevelTests BakedFile_MatchesTheBaker compares the JSON text and depends on UnityEngine.Random sequences, so it can fail after an engine upgrade. Resources/DevProto/Proto_00.json also ships in release builds (the pack is gated off, but the file stays).
8. Nit - v3 Pack_NN reading is clean. StagePack.ReadLevelInto clears rocks, portals and openCells and resets iced and linkedTo per dragon, and the ShippedChunkRead test covers it. I found no regression.
