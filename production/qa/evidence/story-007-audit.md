## Package-id change: what it touches

Do not change anything until the host app owner confirms the new id. A change touches:

1. `ProjectSettings/ProjectSettings.asset` `applicationIdentifier` (Android, Standalone, iPhone) and `productName`.
2. `AndroidDataBridge.cs:16`: the hard-coded `in.dicodeinfotech.arrowqubepuzzle.UnityAdBridge`. The native host must expose the class under the same new name; otherwise wrap the call in try/catch and read the class name from `Application.identifier`.
3. The native host app / launcher: package, `UnityAdBridge`, and the `game_config_json` intent extra (the Unity project does not contain these files).
4. `GoogleMobileAdsSettings.asset` and `AndroidManifest.xml` of the AdMob plugin: real app id once the new AdMob app exists, plus the unit ids the host returns.
5. Save and prefs: the new package id alone gives a fresh `persistentDataPath`, which satisfies AC6. If the old id is kept for any reason, add a campaign id to `SaveData` and rename the file and PlayerPrefs keys.
6. `LevelTracker.cs:10`: the endpoint, or add a game id to the form.
7. Signing keystore and Play Console listing (outside this repo).

## Prioritised fix list

1. **P0, splash**: add the missing space in `SplashScreen.uxml:8` (`title="" class="neon-progress"`). Re-run Play and confirm the progress bar fills and the Console is clear. Without this the splash throws every launch.
2. **P1, identity**: decide the new package id and product name with the host app owner, then apply the list above. This closes AC1 and AC6 together.
3. **P1, host contract**: confirm with the backend owner that the host app's `game_config_json` and `UnityAdBridge` are for the new game (AC2).
4. **P2, `SendDataToAndroid`**: wrap the Android call in try/catch so a missing host class cannot break an ad callback.
5. **P2, `LevelTracker`**: point it at the new game's endpoint or add a game id before any release build.
6. **P3, tidy**: rename `.neon-progress` (class name only), update the obsolete `RegisterUIReloadCallback` calls, and clean the stale comments (`Dot.cs`, `GameFlowManager.cs:12`, `ArrowPalette.cs:14`).
7. **Not verifiable here**: banner, interstitial, rewarded and native ads on a real Android device with test ids, the full Splash to next-level loop on device, and a 10-minute console-clean session. These need a device build.
