# Test Plan: EditMode logic tests (2026-10-20)

> **Scope**: Stories 001, 002, 003, 005 (save) and 008 (palette), logic only. Visual criteria stay with the screenshot evidence in `production/qa/evidence/`.
> **Status**: written, **not yet run** (no Unity Editor was used when these were authored). See "First run" below.

## Where the tests live

`Assets/Tests/EditMode/Editor/`. The game scripts have no `.asmdef`, so they compile into the default `Assembly-CSharp` (runtime code) and `Assembly-CSharp-Editor` (everything under `Scripts/Editor/`). A test assembly built from an `.asmdef` cannot reference either, so the tests sit in a folder named `Editor` and compile into `Assembly-CSharp-Editor`, which can see both. `com.unity.test-framework` 1.8.0 is already in `Packages/manifest.json`. Naming follows `.claude/rules/test-standards.md`: class `[System]Tests`, method `Scenario_Expected`.

## First run

The Editor is open on this project, so a batch `unity test` would collide with the project lock. Two options:

1. Through the open Editor (Pipeline CLI): `unity command list_tests --mode EditMode`, then `unity command run_tests --mode EditMode` (check the exact flags with `unity command --query run_tests`).
2. Headless, Editor closed: `unity test E:/UnityProjects/ArrowPuzzleGameDICode --mode EditMode --report-format junit --output production/qa/edit-mode-results.xml --allow-install --timeout 900`.

**Unverified assumptions to check on that first run** (nothing was compiled):
- The `Assembly-CSharp-Editor` placement compiles with `using NUnit.Framework;`. If the compiler reports that `NUnit` cannot be found, the fix is to add a game-code `.asmdef` (which means confirming PrimeTween, Input System and GoogleMobileAds references), not to change the tests.
- `BakedCampaignTests` loads `Resources/Levels/Chunk_*.bytes` and runs the solver on all 1,500 levels; it is marked `[Category("Baked")]` with a 5 minute timeout. If it is too slow, exclude it with `--category "!Baked"`.
- Any failure on a **fixed seed** (for example `CarveFull_SomeSeedCoversTheWholeBoard...`) should be read as "my assumption about that seed was wrong", not necessarily a game bug. The assertions were written from the code, not observed.

## Not covered (and why)

| Criterion | Reason |
|---|---|
| 001 AC-2/AC-3/AC-4 at runtime: padlock badge, shake with no life lost, unlock at count zero, bump on a locked arrow, hint skips locks, restart resets counters | The behaviour lives in `ArrowController`, a `MonoBehaviour` that needs a `GridBuilder`, PrimeTween and a scene. It needs a PlayMode test. The same rule is covered in `LevelSolverTests` through the solver's model, not through the component. |
| 002 AC-4 (new seed constants differ from the old game) | `CampaignSalt`, `SeedStride` and the old chunks are private/historical. Needs a one-off comparison against the old `Chunk_*.bytes` from git history. |
| 002 AC-7 (re-baking twice is byte-identical) | Needs two real bakes (`WriteAll` deletes and rewrites `Resources/Levels`, which a unit test must not do). Compare hashes of the two outputs manually. |
| 003 AC-1/AC-5 (shapes tracked in git, no old shape left) | Git state, not code. |
| 003 AC-2/AC-3 (preview masks, each shape once per pass) | Covered by `Preview Shape Masks` output in `production/qa/evidence/story-003-shape-preview.txt`. `ShapeIndexFor` is private and tied to the shape folder; a test would need reflection or an editor seam. |
| 005 AC-3/AC-4 (map tap rules, smooth scroll with 1,500 levels), 005 progress logic in `LevelLoader.AdvanceLevel` / `SelectLevel` | `LevelLoader` is a scene `MonoBehaviour` and `SaveSystem.Data` reads and writes under `persistentDataPath`. PlayMode test or a player run (`EvidenceCapture`). |
| 008 visual criteria | Screenshot evidence, not automatable (see `.claude/docs/coding-standards.md`, "What NOT to Automate"). |
| Bump and hint colours distinct from the palette | `bumpColor`/`hintColor` are serialized fields on `ArrowController`; the palette tests check the palette side (hue, ink-likeness) only. |
